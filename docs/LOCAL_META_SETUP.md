# Run Voice Notes locally and receive WhatsApp voice messages

This guide starts with a fresh checkout. Upload and live microphone features need an OpenAI Platform key. The WhatsApp inbox also needs a Meta app, a WhatsApp Business Account (WABA), a WhatsApp test or business number, and a public HTTPS webhook. The Flutter app connects to FastAPI using a separate, locally generated app access token.

Keep all credentials in `backend/.env` on the backend machine. The file is ignored by Git. Never publish it, paste tokens into an issue, or put a token in Flutter `--dart-define` arguments: those arguments can appear in processes and compiled web assets.

## 1. Clone the webhook debugging branch

```bash
git clone https://github.com/Christine-yueyue/eHospital-VoicePipeline.git voice-text-project
cd voice-text-project
git switch --track origin/codex/webhook-debugging
```

The explicit branch selection is needed while this work remains unmerged. Later, use the branch containing this guide.

## 2. Install local prerequisites

- Python 3.11 or newer, Git, and a browser.
- Flutter with Dart 3.10 or newer; check `flutter doctor`. For iOS, use macOS with the full Xcode installation and configure signing for a physical device.
- FFmpeg on `PATH` for WhatsApp OGG/Opus voice notes. On macOS: `brew install ffmpeg`; on other systems install it with your package manager. Verify with `ffmpeg -version`.
- An [OpenAI Platform API key](https://platform.openai.com/api-keys) with access to the configured transcription and translation models. This is separate from a ChatGPT subscription and from all Meta tokens.
- For WhatsApp, a [Meta for Developers app](https://developers.facebook.com/apps/) with the WhatsApp product and access to a WABA/test number, plus a public HTTPS forwarder such as [Cloudflare Quick Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/). On macOS, `brew install cloudflared` installs the tunnel client.

The commands below use a macOS/Linux shell. On Windows, create the virtual environment with `py -3 -m venv .venv`, activate it with `.venv\Scripts\Activate.ps1` in PowerShell, and use `python` in the subsequent commands.

## 3. Configure and start FastAPI

From the repository root:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python ../scripts/init_env.py
```

`scripts/init_env.py` creates `backend/.env` with private file permissions and random, distinct `APP_ACCESS_TOKEN` and `WHATSAPP_VERIFY_TOKEN` values. It prints neither value and leaves an existing `.env` untouched. Edit `backend/.env` locally:

| Setting | Where to get it | Used for |
| --- | --- | --- |
| `OPENAI_API_KEY` | OpenAI Platform | Transcription, translation, and live mode |
| `APP_ACCESS_TOKEN` | Generated by the init script | Login from Flutter to this FastAPI backend |
| `WHATSAPP_VERIFY_TOKEN` | Generated by the init script; enter the same value in Meta's callback form | GET webhook verification only |
| `WHATSAPP_ACCESS_TOKEN` | Meta WhatsApp API Setup or an authorized system user | Fetch WhatsApp media from Graph API |
| `WHATSAPP_PHONE_NUMBER_ID` | Meta WhatsApp API Setup | Select the receiving business number |
| `WHATSAPP_WABA_ID` | Meta WhatsApp API Setup | Select the business account to accept events from |
| `WHATSAPP_APP_SECRET` | Meta App Settings → Basic | Verify signed POST webhook requests |
| `WHATSAPP_GRAPH_VERSION` | A supported Graph API version shown in Meta (format `vNN.N`) | Meta media requests |
| `WHATSAPP_ALLOWED_SENDERS` | Your test sender's country code and number, digits only | Optional inbound allowlist |

For the first local app connection, set `OPENAI_API_KEY`; the WhatsApp fields can be filled later. `TRANSCRIPTION_MODEL` and `TRANSLATION_MODEL` have defaults in `.env.example`. Check that the selected models are available to your OpenAI project. If the web frontend uses a different origin than the default local port 5174, add that exact origin to `ALLOWED_ORIGINS` in `.env`.

Start FastAPI **from `backend/`**:

```bash
python -m uvicorn app:app --host 127.0.0.1 --port 8003 --no-access-log
```

In another terminal, `curl -fsS http://127.0.0.1:8003/health` should return a JSON response with `status: ok`. Keep the backend terminal open. If you edit `.env`, restart FastAPI: `python-dotenv` reads the file at startup and does not override environment variables already exported in the shell. Clear a stale exported variable such as `APP_ACCESS_TOKEN` before restarting if necessary.

`--no-access-log` prevents GET webhook verify tokens in query strings from appearing in access logs. The webhook's dedicated log records arrival, signature result, response status, and queue/processing stages without request bodies, phone numbers, media IDs, or secrets.

## 4. Set up the Meta app and WhatsApp account

1. In [Meta for Developers](https://developers.facebook.com/apps/), create or select the app that will own the WhatsApp integration and add the **WhatsApp** product. Open **WhatsApp → API Setup**. Copy the **Phone number ID** and **WhatsApp Business Account ID** into the matching `.env` fields. Confirm the displayed business/test number is the number your personal phone will message.
2. In **App Settings → Basic**, copy this same app's **App Secret** to `WHATSAPP_APP_SECRET`. The secret signs incoming POSTs; it is not the verify token and not the API access token.
3. In WhatsApp API Setup, obtain an access token authorized for this app and WABA and put it in `WHATSAPP_ACCESS_TOKEN`. A dashboard test token can expire; for durable use, create an appropriately authorized system-user token in Meta Business Settings, assign the app and WABA, and grant the WhatsApp messaging/management permissions required by your setup. Check the permissions and expiry shown in your own Meta account. Never use `APP_ACCESS_TOKEN` or `OPENAI_API_KEY` here.
4. Set `WHATSAPP_GRAPH_VERSION` to a version supported by the Meta API Setup/Graph API you are using (for example, the `vNN.N` format), and set `WHATSAPP_ALLOWED_SENDERS` to your personal test sender's full country code plus digits, without `+`, spaces, or dashes. This allowlist is optional, but if set, a mismatch causes a signed audio event to be acknowledged without entering the inbox. `WHATSAPP_TARGET_LANGUAGE` defaults to `fr` and also accepts `en`.
5. In Meta's Webhooks configuration, select the **`whatsapp_business_account`** object and subscribe to the **`messages`** field. Separately, confirm that this app is subscribed to the intended WABA. With a token authorized for the account, Meta's Graph API Explorer can inspect `GET /<WABA_ID>/subscribed_apps` and `GET /<WABA_ID>/phone_numbers`; the latter should contain your configured phone-number ID. Check for any WABA-level callback override. Callback verification alone establishes neither subscription.
6. Follow the Development/Live, app-role, test-number, and authorized-recipient rules shown in the current Meta dashboard. These restrictions depend on the account and app; a successful outbound template send or synthetic dashboard test does not prove real inbound delivery.

Meta's UI labels can change. The important identities are the app whose secret signs the webhook, the WABA to which that app is subscribed, and the phone-number ID from the incoming event. They must correspond to the `.env` values.

## 5. Start and connect the Flutter frontend

Open a **second terminal** in `voice-text-project/frontend`:

```bash
flutter pub get
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 5174
```

Open `http://127.0.0.1:5174` in a browser. In **Connection settings**, set **Server address** to `http://127.0.0.1:8003`, enter the `APP_ACCESS_TOKEN` from your local `backend/.env`, and select **Connect**. Keep this token out of the command line and frontend source. The app keeps it in memory for this prototype. A wrong app token gives a `401` from `/api/config`; it has no bearing on WhatsApp webhook POSTs.

For an iOS simulator, follow `flutter doctor` and run `flutter run -d ios`. On a physical iPhone in a debug build, start FastAPI with `--host 0.0.0.0` on a trusted private LAN, use the Mac's LAN IP rather than `127.0.0.1` in Connection settings, and permit the local firewall connection. Production/mobile release builds need an HTTPS backend with a trusted certificate.

## 6. Expose and verify the WhatsApp webhook

With FastAPI still running on port 8003, open a **third terminal**:

```bash
cloudflared tunnel --url http://127.0.0.1:8003
```

Copy the temporary `https://...trycloudflare.com` hostname printed by Cloudflare. In Meta's WhatsApp/Webhooks callback settings, enter `https://<current-hostname>/webhooks/whatsapp` as the **Callback URL** and enter exactly the `WHATSAPP_VERIFY_TOKEN` from `backend/.env` as the **Verify token**. Use Meta's Verify and Save action. Cloudflare must stay running; a new Quick Tunnel often has a new hostname, so update the Meta callback when it changes. The FastAPI route accepts GET verification and signed POST events at this exact path.

The quick tunnel forwards the entire local server for development. Use a controlled HTTPS proxy/tunnel that exposes only the required webhook route for a lasting deployment. Do not turn on Uvicorn access logs while handling GET verification requests, because their query string includes the verify token.

## 7. Test each stage

1. Visit `http://127.0.0.1:8003/health` to confirm local FastAPI, then connect the Flutter app using the separate app token.
2. Verify the callback in Meta. Successful GET verification proves the URL and verify token work; it does not prove signed POST delivery or WABA/field subscriptions.
3. Use Meta's **Test** action for the `messages` webhook field once. Look for `WhatsApp webhook POST reached.` and `signature=passed` in the backend terminal. A synthetic test can report zero matching audio messages because it may not use your configured WABA/phone number or may represent a text/status event.
4. From the personal sender allowed by your configuration, send a **new WhatsApp voice note** to the business/test number shown in API Setup. A text message is acknowledged but never queued. For a real voice note, expect `1 matching audio message(s)`, `1 newly queued`, `processing started`, `audio downloaded`, `transcription succeeded`, and `processing completed`. The inbox should show the transcript and translation. Refresh the inbox if needed; it polls every five seconds while open.
5. To run code checks without contacting Meta or OpenAI, run `python -m pytest -q` from the activated backend virtual environment. From `frontend/`, run `flutter analyze` and `flutter test`.

## 8. Diagnose a failed stage

| Symptom | Check |
| --- | --- |
| App says it cannot connect | Backend is listening on 8003, the address matches the device, HTTPS is valid for release builds, and `ALLOWED_ORIGINS` includes a custom web origin. |
| `/api/config` returns `401` | `APP_ACCESS_TOKEN` in Connection settings must match the backend's `.env`; restart after editing it. |
| Meta GET verification fails | Exact HTTPS callback path, running tunnel, and `WHATSAPP_VERIFY_TOKEN`. Do not log or share the GET query. |
| No POST log after a real message | The current tunnel hostname, Meta app-to-WABA subscription, `messages` field subscription, callback override, and account/test-number restrictions. |
| POST returns `403 signature=failed` | `WHATSAPP_APP_SECRET` must be from the Meta app that sends the event. Signature checks must remain enabled. |
| POST returns `200`, but no audio enters the inbox | Confirm an audio message, WABA ID, phone-number ID, sender allowlist, message age, and whether it is a duplicate. Text/status events normally queue nothing. |
| Inbox reports Meta token rejected (`401` or Graph code `190`) | Replace expired/invalid `WHATSAPP_ACCESS_TOKEN` in `backend/.env`, restart FastAPI, then select **Retry** on the failed item. This is unrelated to the app login token or OpenAI key. |
| Inbox reports Meta access denied (`403`) | Check the Meta token's permissions, WABA and phone-number access, then select **Retry**. |
| Media downloads but transcription fails | Check `OPENAI_API_KEY`, model access/billing, FFmpeg, and the audio format. |

WhatsApp audio and transcripts are stored under `backend/data/` when **Save to Database** is on; the SQLite inbox also uses that local directory. These files and `backend/.env` are excluded from Git. Stop the three programs with Ctrl+C in their respective backend, frontend, and tunnel terminals. Restart FastAPI after changing backend configuration.
